# Operator-ingress fixed choice and alternative-source representation Fidelity recovery 001

## Scope, method, and verdict

This is one bounded, report-only recovery after PR 2104, against merged `main`
after PR 2105. It examines only the named fixed choice/source/representation
island, its exact consumers and serializers, adjacent general closed-choice
shape, relevant historical Events/projectors, tests, reports, and the Book. It
does not reopen capture validation, binding, selection, source recovery,
meaning warrant, BOGE applicability, or replay policy except where one of those
surfaces consumes an exact island result.

Repository-wide symbol and call searches establish the controlling topology:
the active ingress stops after strict representation examination and quiescent
return. No non-test call to the three constructors/formatters remains. Tests
directly manufacture the only current choice, representation, recording,
presentation, binding, and downstream-consumption road. Projector branches can
still preserve matching historical or synthetic Events, but are not semantic
consumers of the Python producers.

The island is **mixed**, not wholly invalid. Its fixed strings, options, source
identities, mappings, pure choice constructor, formatter, and fingerprint are
application-owned local representation material. That ownership permits Seed
to declare and format them, but does not make the choice presently applicable,
the two options exhaustive for a current consumer, their propositions
operator-derived, or either alternative a participant in an applicable exact
set. `AlternativeSourceRepresentation` combines a faithful attributed
source-to-alternative relation with an unverified formation-occurrence
reference and the unsupported positive participation assertion. With no live
producer or non-test consumer, production change is not warranted in this
report. The next honest inch is a bounded deletion/decomposition change that
first identifies whether any application-local declaration or pure formatter
is actually worth retaining.

The settled production boundary remains:

```text
CapturedOperatorMaterial
→ strict representation examination
→ decoded non-EOF ingress occurrence
→ bounded projection
→ quiescent return
→ continuing outer console operation
```

## Constitutional ledger used in this recovery

The Book recognizes closed-choice representation, but it does not bless an
arbitrary concrete set. It says a responsible representation occurrence forms
an alternative after purpose-local eligibility; the alternative (not its
source) may then participate in the exact set. It expressly says multiplicity
does not establish a bounded set and set establishment does not establish
participation. Participation is separately warranted for the declared purpose.
It also says direct construction proves constructibility, an artifact is not an
act, array inclusion is not constitutional participation, and representation
formation is not presentation/emission.

Accordingly this report preserves all of these separations:

```text
application-owned source != operator-origin source
source identity != source proposition truth
application attribution != constitutional authority
choice-set definition != present applicability
alternative formation != presentation occurrence
representation relation != meaning warrant
rendered label != represented proposition
rendered detail != source proposition
set membership != eligible participation
eligible participation != actual formation
formation != presentation
presentation != operator selection
exact-set participation != current consumer need
fingerprint integrity != substantive warrant
producer occurrence reference != actual producer occurrence
test construction != production reachability
Unknown != false != refused != inapplicable
```

The Book's example of this two-alternative use is conditional: alternatives
whose local participation **is established** may express the attributed
potential-goal and local-stop meanings. It calls the set non-universal. That
prose neither supplies today's consumer nor substitutes for eligibility,
formation, or participation occurrences deleted or disconnected in PRs
2101–2104. No Book correction is needed to reach this result.

## Recovery A — fixed choice-set construction

### Exact application declarations

`CHOICE_SET_REF` is the developer-authored identity
`operator-ingress-common-grammar:v1:two-alternative`. `PROMPT` is the
developer-authored instruction `Select one alternative by its exact token:`.
Neither value carries a consumer, applicability basis, formation occurrence,
exhaustiveness warrant, or operator origin.

The two `OPTIONS` rows are:

| Token | Presented alternative ref | Label | Detail / claimed purpose | Source relation | Authority, scope, provenance, Unknowns |
| --- | --- | --- | --- | --- | --- |
| `1` | `common-grammar-acquisition` | `Select bounded common-grammar acquisition alternative.` | Detail is empty. The label proposes local selection of a bounded acquisition alternative. | Later mapped by `ALTERNATIVE_SOURCES` to the application potential-goal source; the option itself carries no source field. | Developer-owned constant; no per-option provenance/scope/limits/Unknowns. Operator origin, present applicability, eligibility, formation, participation, exhaustiveness, and authority are Unknown. |
| `2` | `local-stop` | `Select local stopping alternative.` | Detail is empty. The label proposes local selection of a stopping alternative. | Later mapped to the application local-stop source; the option itself carries no source field. | Same local declaration limits. It does not prove an established stop or authority to stop. Formation, participation, applicability, and consumer are Unknown. |

`common_grammar_choice_set(presentation_ref)` places those constants in a
`PresentedClosedChoiceSet`, attaches caller-provided presentation identity and
one module provenance string, and returns it. It performs no Event lookup,
eligibility check, formation validation, participation examination, recording,
presentation, or consumer/applicability check.

The general abstraction guarantees only: nonempty `choice_set_ref`, unique
tokens within the tuple, exact retention of prompt/options/presentation ref,
Unknowns/conflicts, and a deterministic content coordinate over the set fields
and convention. It does **not** require a nonempty option set or presentation
ref, claim exhaustiveness, candidate eligibility, alternative formation,
participation, presentability, presentation, selection, or authority.

The application constructor adds the stronger *shape* of one fixed named,
binary, numeric, affirmative/local-stop presentation and describes it as an
application-owned probe. In ordinary Python terms its tuple is exhaustive for
binding against that object. Constitutionally, however, it has no evidence that
these are all applicable alternatives now, that an operator must choose, or
that Seed may presently present them. Its standing is therefore **faithful only
conditionally / mixed**: faithful local presentation material, unsupported if
treated as a self-authenticating applicable closed choice.

`common_grammar_representation_lineages` is a pure tuple constructor, not an
examiner or recorder. It iterates the choice options; map misses raise rather
than becoming Unknown. It says substantially more than “the application says A
represents S”: it positively says A participates in the exact presented set,

explicitly say the set is presently applicable or that source meaning is

participation and occurrence coordinates imply standing they do not establish.
The result is **mixed** and requires decomposition before preservation as a

remove or separately produce participation; represent a producer reference as
unverified attribution unless a responsible occurrence owns it; preserve the

## Recovery D — producer-occurrence truthfulness

The helper does not access a ledger. It validates neither existence nor Event
kind, workspace, session, attempt, dimensions identity, lineage, nor causal
production. It merely copies `producer_occurrence_ref` into every row.

The surviving test fixture passes `representation:helper`, then records an
`alternatives_represented` Event whose dimensions identity is that string. Thus
the rows name the future record's *representation identity*, not its eventual
Event identity. The fixture's downstream recovery checker verifies equality
between the row reference and recorded Event **payload dimensions identity**;
it still does not prove the helper was called by that Event occurrence.

Former production behaved the same way: it generated a representation identity,
constructed rows with it, and only afterward recorded an
`alternatives_represented` Event. The Event's actual `id` was different. The
former code therefore supplied an exact declared identity used by the record,
not an already-recorded producer Event. Chronology and consistency are evidence
of former implementation intent, not validation inside the helper.

Classification: the field is **attributed testimony / unsupported occurrence
standing**. “Object contains producer reference” is not “that occurrence
produced the representation.” Adding validation is premature until a current
consumer and responsible producer are established.

## Recovery E — exact-set participation

The Book requires a separately warranted participation relation for a declared
purpose, local scope, evidence, producer, occurrence, and surviving Unknowns.
Candidate eligibility is distinct and, on the Book's conditional closed-choice
road, precedes responsible alternative formation; neither eligibility nor
array/set construction establishes participation.

The deleted eligibility producer formerly returned a positive result, but the
old tail did not consume that return when it called the choice or representation
constructors. It recorded eligibility chronologically and discarded the exact
result. Eligibility was therefore described as a prerequisite but never an
input to formation or participation. Today no live eligibility result exists.
The helper does not distinguish candidate formation from participation: it
constructs a row and asserts both by implication in one return.

`PresentedClosedChoiceSet` construction establishes a deterministic Python
tuple and unique token membership, not constitutional participation. Its
fingerprint proves only integrity/identity of set-shaped content. The
representation fingerprint similarly proves deterministic integrity of the
serialized rows, not their truth or warrant. The only strict consumer of the
participation literal is the disconnected source-recovery fixture road; it
refuses mutation. That demonstrates exact consumption, not upstream authority.
No current non-test consumer requires the relation.

Present classification: **unsupported positive claim**. If rephrased as “the
application declares intended participation conditional on applicable purpose,
eligibility and responsible formation,” it could be faithful conditional
testimony, but that is not the current positive literal or empty-Unknown shape.

## Recovery F — formation, recording, and presentation

Neither surviving helper records anything. `common_grammar_choice_set` and
`common_grammar_representation_lineages` construct Python values. They are not
examiners. They are not constitutional recorders. A frozen dataclass improves
value integrity but does not establish formation occurrence.

No current production Event records choice formation, alternative formation,
representation formation, or set participation. Historical Event kinds remain
projectable:

* `alternatives_represented` records that an occurrence claimed a payload of
  representations, a set fingerprint, and a representation fingerprint. Its
  name/dimensions can testify that representation was claimed and preserved;
  without responsible producer validation it does not independently prove the
  source relations, formation, or participation.
* `presentation_occurred` is a distinct presentation claim. It does not form
  alternatives or establish participation.
* `probe_produced` historically carried rendered content/set identity; it is
  distinct from both formation and presentation.

Surviving tests explicitly construct rows and then manufacture an
`alternatives_represented` Event, then separately manufacture a
`presentation_occurred` Event. That is historical scaffold / direct contract
testimony, expressly documented as not active production. Former production did
record these kinds in order, but that producer road is deleted.

Formation responsibility therefore has no current owner and its exact proving
occurrence is **Unknown**. Presentation, were it to exist, constitutionally
depends on a responsibly formed representation with adequate standing, not
merely on dataclass availability. Projector acceptance demonstrates record
shape preservation, not actual current producer occurrence.

## Recovery G — rendering

The exact pure transformation is:

```text
choice_set.prompt
+ newline
+ for each option in tuple order: token + ". " + presented_label
→ one string (without a trailing newline)
```

It retains prompt, option order, tokens, and labels exactly apart from inserted
separator text. It omits `choice_set_ref`, fingerprint, `presentation_ref`,
provenance, Unknowns, conflicts, presented-alternative refs, every
`presented_detail`, source refs/roles/propositions, representation purpose,
relation, participation, attribution, limits, provenance, loss, and occurrence.
Therefore it cannot reconstruct source identity or meaning. Even the current
empty details are not rendered; a general input with nonempty detail loses
them.

`RENDERING_KNOWN_LOSS` accurately says the rendered label is compressed and
lacks the complete proposition. It is **not complete** as a general loss
inventory because it omits all the coordinates above, notably detail and
alternative/source identities. It is complete enough only for the present
disconnected strict consumer's narrow requirement to preserve that one warning;
no current runtime consumer relies on reconstruction.

`render_probe` is independently a faithful pure formatter if its contract is
only the exact prompt/token/label string. It remains reusable with general
`PresentedClosedChoiceSet` values and does not itself claim applicability,
formation, presentation, or source meaning. Its name is historical, but deletion
of the probe road does not make formatting mathematically unfaithful.

## Decomposition analysis

### Candidate 1 — pure rendering only

Preserve/isolate `render_probe` only if a general or future exact formatter
consumer is identified. It is independently faithful and reusable for the
prompt/token/label contract. Removing it now changes no runtime behavior, breaks
no current semantic consumer, and changes no replay. A dedicated unit test would
be needed if preserved as an intentional public/local contract. Its loss would
remove only formatting behavior, not representation or meaning distinctions.
Deletion/preservation is sufficiently specified, but consumer need is Unknown.

### Candidate 2 — fixed choice constants and constructor

These form coherent application-local material but are also obsolete
fixed-probe scaffold: no current consumer makes the declared purpose applicable.
Deletion changes no runtime or replay, but requires removing/replacing direct
fixtures that depend on exact identities/fingerprints. It breaks no established
non-test consumer. Wholesale deletion would lose the historical local proposal,
not a warranted constitutional choice. The boundary is sufficiently specified
for bounded deletion after fixture dependencies are mapped; preservation is
conditional, not presently justified by reachability.

### Candidate 3 — fixed source declarations

`SOURCE_PROPOSITIONS`, `ALTERNATIVE_SOURCES`, and
`POTENTIAL_GOAL_SOURCE_REF` can stand as attributed application proposals
independently of presentation or BOGE, provided they are not promoted to standing
or operator meaning. Runtime behavior would not change if deleted today; tests
and local testimony/warrant fixtures would require targeted replacement/removal.
Historical payloads/projectors do not need constants to replay. Deletion could
erase a still-useful application testimony fixture, so exact retention should
follow a consumer recovery rather than assumption. This boundary is a candidate
for bounded deletion, with separation from meaning-testimony consumers required.

### Candidate 4 — alternative representation helper

The dataclass/helper/fingerprint family mixes faithful A→application-source
testimony, unsupported formation implication, unsupported participation, and an
unverified producer reference. Runtime deletion changes nothing; tests for
source recovery, meaning warrant and durable refusal currently use its payload
and would need neutral warranted fixtures or deletion according to their own
recoveries. Historical replay is unchanged because Events are data and
projectors do not import the dataclass. No non-test consumer breaks. Preserve
the fingerprint only if a surviving serialized-row consumer remains. The helper
requires decomposition if retained; its current positive shape is sufficiently
specified for deletion if no consumer is found.

### Candidate 5 — entire application-specific producer island

This boundary includes only fixed constants/maps, fixed constructor/formatter,
row dataclass/helper and representation fingerprint. It excludes the general
closed-choice module, historical projectors/Event payloads, source-recovery and
meaning-warrant helpers, BOGE, and exports. Deletion changes no active runtime
behavior and no historical replay; it causes extensive direct-fixture test
changes and may require decoupling separate consumer tests. It breaks no
established non-test semantic consumer. Wholesale deletion risks losing the
faithful distinction between application declaration and operator origin unless
downstream fixtures represent it independently. Therefore deletion is bounded
but not yet the next automatic action: first decompose faithful testimony from
unsupported participation/occurrence, or demonstrate that even the faithful
material has no intended consumer.
