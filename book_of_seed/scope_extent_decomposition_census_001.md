# Scope and extent decomposition census 001

## Question

Do `scope` and `extent` name the same Seed distinction?

The immediate pressure is a bounded operation that may address fewer than
every exact coordinate available to it.

## Admission boundary

Neither word occurs in active Book admission. `scope` remains admitted only
to Rosetta. `extent` occurs in historical investigations and implementation
explanation but is absent from both Book and Rosetta admission.

The former `08.Scope.A` wrapper said that Scope bounded subjects, relations,
Acts, occurrences, results, and Localities. Commit `e2993cd1` withdrew it
because those exact coordinates already carried their own boundaries and no
Scope identity, occurrence, Act, relation, or result independently varied.

This census does not restore that wrapper.

## Exact extent control

The live same-position Applicability road supplies a bounded cross-set of
exact subject coordinates. Hold its two input coordinate families unchanged:

```text
2 exact shared-position result coordinates
×
2 exact recorded-pair Compare result coordinates
=
4 exact cross-set coordinates
```

Record one Applicability Act and read again. Then record the remaining three
Acts without adding either input family.

```text
reading B1
    exact cross-set coordinates    4
    Applicability Acts             1
    exhaustive                     no

reading B2
    exact cross-set coordinates    4
    Applicability Acts             4
    exhaustive                     yes
```

The exact cross-set does not change. Exhaustion does.

Therefore an exact extent, as ordinary explanation, does not imply `every`:

```text
exact bounded coordinates
!=
every exact bounded coordinate has the addressed Act
```

`every` retains its admitted meaning: no coordinate in the exact bounded
extent is omitted. The extent says which coordinates the exhaustion question
is about; it does not answer that question.

## Scope pressure

Historical and current ordinary uses of `scope` do more than name those
coordinates. Depending on the sentence, the word compresses some combination
of:

```text
exact subject coordinates
addressed reading boundary
exact Act
Locality
source coordinates
implementation lifetime
```

The same exact cross-set can be read without an Act, receive one Act, or
receive Acts exhaustively. Its coordinates alone do not say which Act occurs.
Conversely, naming an Act and Locality does not say which current coordinates
are bounded by an addressed reading.

Thus `scope` cannot be substituted for `extent`:

```text
extent
    exact coordinate family
    + exact addressed boundary

scope
    ordinary compression whose expansion depends on what is being bounded
```

The word `scope` also names Python lexical regions, pytest fixture lifetimes,
and SQLite transaction contexts in repository mechanics. Those meanings share
no Seed occurrence or relation.

## Disposition

```text
exact                         active Book coordinate
boundary / bounded            active Book coordinates
every / exhaustive            active bounded-exhaustion distinction

extent                         useful explanation of the exact bounded
                               coordinates under consideration;
                               no independent Book coordinate

scope                          Rosetta / implementation compression;
                               expand into the exact coordinates, Act,
                               Locality, and boundary required by the use
```

Do not admit `Scope` or `Extent` to the Book. Do not create an extent
occurrence, Scope relation, work object, or completion object.

The focused control adds no runtime road. It only proves that the same four
exact coordinates can be incomplete and exhaustive at different exact
readings.
