# Applicability binding candidacy census 001

## Question

Can the existing runtime address bounded exact subjects with Applicability
without first recording one subject-to-Act binding for every Cartesian member?

This census changes no active Book clause, runtime physiology, Act, result,
relation, identity, or constitutional kind.

## Exact current road

The same-position Measurement and pair-finding Compare road reads two exact
sets through current coordinates:

```text
same-position Measurement result occurrences
recorded pair-Compare result occurrences
```

Host mechanics then form every pair:

```text
for each same-position Measurement result S
    for each pair-Compare result C
        read exact combined inputs (S, C)
        record one Compare subject-to-Act binding for (S, C)
```

Only after every prospective Compare binding is durable does the runtime begin
the Applicability lifecycle for each binding.

## Stoppability discriminator

The two-by-two fixture supplies two exact results on each side. After the


Every binding records the exact two input references, Compare Act identity,

This proves that the current road makes each possible combination durable
before Applicability distinguishes it.

## Binding and candidacy

The two distinctions are not interchangeable.

One exact subject-to-Act binding states:

```text
these exact subjects
this exact Act
this Locality
```

Candidacy of bounded inputs would need only enough exact physiology for
Applicability to test the combinations warranted within that bound. It does
not by itself warrant a durable prospective Compare binding for every
combination the host can mechanically inspect.

Deleting the historical Candidate noun did not delete this expansion. It moved
the candidate-shaped durable state into the pre-Applicability Compare binding
floor.

### Existing Applicability results

## Subtraction attempts

### Rename Compare binding as candidacy

Fails. The occurrence still records exact prospective Compare Act and result
identities for one Cartesian member. Changing its name loses no expansion.

### Keep only positive Compare bindings

Fails. Positive and negative are established by Applicability results. Host
mechanics would decide the result before the Seed Applicability Act and erase
exact negative results.

### Record one Applicability binding per pair without Compare bindings

Fails the discriminator. It retains one durable candidate-shaped binding per
Cartesian member under another kind.

### Record one Applicability lifecycle over both bounded input sets

Not presently warranted. No existing Act occurrence, binding, or result has
those sets as its exact subjects, and current coordinates alone are not an
occurrence.

