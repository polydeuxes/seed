# Byte-pair input Applicability census 001

## Question

Does live byte-pair input Applicability establish a result that can differ, or
does it repeat the exact source result-position coordinates before every
byte-pair Measurement?

This census changes no active Book clause, runtime occurrence, Act, result,
relation, identity, or reader.

## Active inward order

For every exact byte Measurement result just recorded, the operator operation
calls the byte-pair lifecycle. The lifecycle records:

```text
exact byte-result position
        ↓
Applicability binding occurrence
        ↓
Measurement binding occurrence
        ↓
Applicability Act occurrence
        ↓
Applicability result occurrence
        ↓
Measurement Act occurrence
        ↓
byte-pair Measurement result occurrence
```

Unlike the ordinary recurrent shared-position control, this lifecycle is
produced by the active inward process.

## Verdict census

`_pair_input_applicability_from_exact_source(...)` assigns:

```text
applicability = "applicable"
```

unconditionally.

No input coordinate, Locality, movement coordinate, source content, or
boundary can produce `inapplicable`. The producer therefore records one
positive Applicability Act/result for every exact byte-result position it
accepts.

## Exact subject before Applicability

Before the first binding event, the lifecycle has already read and validated:

```text
exact byte Measurement result occurrence
exact result-local position
exact source material occurrence references
exact completeness boundary
source Locality coordinates
result-position movement occurrence when movement occurred
destination Locality
```

That exact result position is the complete input to the byte-pair Measurement.
The Measurement counts adjacent byte pairs throughout the bounded exact source
material addressed by that result position. Applicability neither narrows the
source nor changes the boundary.

## Copied prospective floor

The Applicability binding records the source result position, movement
coordinate, source boundaries, future Applicability identities, and future
Measurement Act identity.

The Measurement binding records the same source result position, movement
coordinate, source boundaries, and future Measurement Act/result identities.

The positive Applicability result repeats the same source address and points
to those prospective identities. The later Measurement result records the
actual varying content:

```text
exact pair content
total pair occurrence count
number of source occurrences containing the pair
recurrence when count exceeds one
exact source result-position references
```

## Negative control

The runtime contains no negative byte-pair input Applicability producer and no
test that obtains one through the public lifecycle. Tests assert only
`applicable` and reject malformed copies of that positive dictionary.

This differs from ordinary shared-position Applicability, whose exact equality
test can return either positive or negative when the laboratory calls it.

## Finding

```text
active inward producer                                established
exact Measurement subject before Applicability       established
positive verdict                                      unconditional
negative verdict                                      impossible
source narrowing by Applicability                     absent
independently variable Applicability distinction      not found
pair count / recurrence variation                     Measurement result
```

Byte-pair input Applicability fails the same first discriminator as
addressed-byte Determination Applicability: its result cannot vary.

## Proposed falsifier

Pressure this live road independently:

```text
exact byte-result position
        ↓
byte-pair Measurement Act occurrence
        ↓
byte-pair Measurement result occurrence
```

Remove only the two prospective binding events and the forced Applicability
Act/result. Preserve:

```text
exact source result position
movement and destination Locality coordinates
source occurrence references
completeness boundary
pair counts and recurrence
Act-before-result order
one result per Act
current-coordinate replay
SQLite reopen
intervening append and mutation refusal
later pair Compare and source-position physiology
```

Do not generalize the result to an Applicability family with independently
variable positive and negative results.

## Amendment after subtraction

The falsifier passed. The active inward road now records the exact source
result position directly on the byte-pair Measurement Act, followed by one
exact Measurement result. The two binding events and forced Applicability
Act/result are absent.

Pair counts, recurrence, movement coordinates, source occurrence references,
current-coordinate replay, restart, mutation refusal, recorded-pair Compare,
and later source-position physiology survive. Reading the result does not
perform Measurement again.

The old callable lifecycle remains only as an independently callable
laboratory control. Ordinary recurrent shared-position Applicability remains
untouched because its authored result can vary.
