# Identity as constitutional grammar: investigation 001

Findings only. This report amends no active Book clause, witness grammar,
runtime, Rosetta entry, admission list, or test.

## Independence and scope

This investigation was performed at repository tip `2dfa3bb7`. Active Book
material supplies constitutional warrant. Machine grammar, runtime, tests, and
history are examined independently as Fidelity or chronology testimony; none
supplies Authority to another.

The question is not whether implementation identifiers are useful. It is
whether active Seed law independently recovers `identity` and `identifies` as
one irreducible constitutional primitive, or whether current uses combine
narrower distinctions:

- opaque machine addressability;
- exact references;
- preservation across a boundary;
- occurrence distinctness;
- subject continuity; and
- one explicitly evidenced `identifies` relation.

The investigation does not infer non-identity merely because two references
differ. It does not substitute sameness, equality, membership, classification,
predication, equivalence, or another primitive. It does not recommend a global
rename or deletion.

## Method

The method follows
`predicate_relation_coordinate_investigation_001.md`:

1. **Vacancy test.** For each use, ask whether some distinction lacks a
   coordinate without Identity.
2. **Elimination test.** Remove only the Identity wording in thought while
   retaining the exact references, occurrences, coordinates, Evidence, and
   relations already carried. Record what becomes impossible.
3. **Chronology.** Determine whether the wording preceded its purported
   distinction or was introduced to justify a later representation or runtime
   refusal.
4. **Cross-domain stress.** Apply the proposed distinction to exact stored
   occurrences, repeated references, preserved Assertions, grammar roots, and
   mathematical material without importing meaning between domains.
5. **Active-Book warrant.** Require an independent active clause for the exact
   constitutional claim. README structure, grammar shape, runtime behavior,
   tests, and commit messages remain testimony.
6. **Negative boundary.** State what each surviving mechanism does not
   establish.

## Result

`identity` is not recovered as one universal constitutional primitive.

The current vocabulary combines at least six materially different surfaces.
Opaque machine addressability is an irreducible implementation mechanism, but
establishes no constitutional Identity relation. Exact references are real
coordinates. Preservation is a real relation. Repetition of one exact
reference does not create another occurrence. The generic README connective
and grammar-root triples are presentation or machine-witness syntax. The exact
evidenced relation assertion `X identifies Y` remains a potentially real
relation whose constitutional content is Unknown.

The result is decomposition, not excision.

## 1. Machine addressability

### Current claim and mechanism

`seed_runtime/identities.py:new_identity` mints a process-unique string under a
prefix. `Event.identity` is a fixed stored coordinate. `EventLedger.get` and
its SQLite implementation use that string as a lookup key. Append-prefix
mechanics, duplicate refusal, restart prefix reservation, exact occurrence
reads, and durable references depend upon it.

### Actual distinction

One opaque address retrieves one stored record. The ledger can refuse a reused
address, locate the append position of an addressed record, and carry that
address in another record.

### Vacancy and elimination

There is a real implementation vacancy: without an opaque key, exact retrieval,
append-boundary addressing, duplicate refusal, and durable reopening require
some other addressing mechanism. Removing the mechanism makes those operations
impossible.

Nothing in minting or comparing the string establishes that the address
constitutionally identifies a subject, that two addressed subjects are one,
or that two different addresses establish two constitutionally different
subjects. Each alleged occurrence still requires its recorded occurrence and
Evidence.

### Disposition

**Irreducible machine address; not constitutional Identity.** Machine
identifiers must not be removed merely because their names contain `identity`.

## 2. README required identifying branches

### Location and current claim

`book_of_seed/README.md` uses `Identifies ...` as the generic connective from a
Responsibility to responsible boundary, subject, Act, Authority, Evidence,
source, provenance, occurrences, results, Standing, preservation records, and
downstream coordinates.

### Actual distinction

Each heading names a coordinate that a responsibility-shaped road may require.
The branch value remains uninstantiated until a responsible occurrence
supplies it.

### Independent warrant and chronology

Commit `e1fd24b4` introduced the complete section in one README-only change.
Its message expressly calls Responsibility the Book's **presentation and
traversal root**, not a constitutional superkind or fixed schema. The current
README likewise says its headings name coordinates and relations.

No numbered active clause was found that establishes one generic
Responsibility-to-every-coordinate `identifies` relation.

### Elimination

If the generic verb is removed while each branch heading and exact requirement
remain, no coordinate, occurrence, Evidence requirement, or relation becomes
inexpressible. The headings already expose what must be carried.

### Disposition

**Reducible presentation shorthand.** Its recurrence cannot warrant a
constitutional Identity relation.

## 3. `01.Standing.F` subject / identity

### Location and current claim

`01.Standing.F` places `subject / identity` first among approximately eight
macro-dimensional families. The clause calls the paired labels bounded
compressions of neighboring coordinates rather than indivisible scalars.

### Chronology and warrant

Commit `ea372752` concluded that the then-active Book did **not**
constitutionalize the historical eight-family map. Its strongest recovery was
approximately eight recurring macro-dimensional families used as bounded
orientation. It describes `subject / identity` as a compression and says a
subject may have several relevant identities.

Commit `c23f9195` then inserted the approximate map into active material. No
independent distinction was recovered that makes Identity irreducible beside
subject. The clause itself continues to deny finality and scalar unity.

### Elimination

Removing `identity` from that orientation pair loses one historical grouping
label. It loses no required field, occurrence, reference, Act, relation, or
consumer behavior.

### Disposition

**Reducible orientation label.** The family supplies no warrant for universal
Identity.

## 4. `01.Source.D.1` occurrence counts

### Location and current claim

`01.Source.D.1` says each exact occurrence reference in a count finding
preserves exact occurrence identity and that repeated reference to one
occurrence cannot create another occurrence or occurrence reference.

### Actual distinction

Repeating one exact occurrence reference does not multiply the occurrence to
which the reference resolves. A count of references is a separately warranted
Measurement.

This does not mean that different reference strings alone establish different
occurrences. Each counted occurrence must be an actual exact occurrence carried
by the bounded Measurement. Two occurrences carrying the same material may be
counted separately only when both occurrences are independently present in the
bounded source population.

### Chronology

Commit `ff9eaa2e` added occurrence identity because runtime refused a repeated
occurrence without active-Book warrant. The first version also introduced
population membership grammar. Commit `07b9eefe` recognized that grammar as
excess and removed it while retaining occurrence identity.

The chronology proves that identity wording answered a runtime refusal. It does
not independently prove Identity as the smallest necessary distinction.

### Elimination

The exact reference plus the explicit non-creation rule expresses the recovered
distinction. Removing the identity word while retaining those coordinates makes
nothing impossible.

### Disposition

**Reducible to exact occurrence reference and non-creation.**

## 5. Assertion continuity and distinctness

### `01.Standing.D.1`

Current material says different exact asserted content identifies a different
Assertion rather than revising the earlier Assertion's identity.

The recovered distinction is non-revision: later different material cannot
rewrite the earlier bounded Assertion and its carried Standing. Another
Assertion requires its own responsible occurrence and exact coordinates.
Different material by itself establishes neither that occurrence nor another
Assertion.

Removing Identity wording loses no distinction when the earlier Assertion
reference, content, Standing, and requirement for another occurrence remain.

**Disposition: reducible.**

### `01.Standing.D.2`

The clause and grammar say preservation carries each earlier Assertion's exact
identity **and exact reference**. The exact reference, carried coordinates, and
preservation relation already occupy the continuity position. No independent
consumer of an additional identity coordinate was recovered.

**Disposition: reducible where paired with exact reference.**

### `01.Standing.E.1`

Current material says each Assertion has a distinct identity and exact
coordinates and lists `input_identity` and `occurrence_identity` among
Applicability coordinates.

The actual distinctions are:

- the exact Assertion subject and reference;
- the exact Act-local input role;
- the exact Act occurrence reference; and
- the separate output Standing boundary.

Where those references and coordinates are carried, Identity adds no further
information. Where they are absent, the word `identity` cannot establish
subject continuity or an occurrence.

**Disposition: reducible when exact coordinates are present; otherwise
Unknown, not supplied by Identity.**

## 6. Yield

### Location and current claim

`02.Acts.A` says Yield preserves exact Act-occurrence identity and result
identity. Machine grammar and tests require those exact names.

### Actual distinction

Yield is an evidenced relation from one exact Act occurrence to one exact
result. Runtime Evidence carries the Act-occurrence address and the recorded
result occurrence address. Same result content in distinct Act occurrences
selects neither result and establishes no Yield relation.

### Vacancy and elimination

The exact Act-occurrence reference and result reference already occupy both
ends of the relation. The Evidence and occurrence witness establish the bounded
relation. Removing Identity wording while retaining those exact references
loses nothing.

### Disposition

**Reducible to exact Act-occurrence and result references.**

## 7. Movement and Locality

### Paired reference and identity

`06.Locality.A` says movement preserves the original Assertion reference and
identity. Where both are present, the exact Assertion reference plus the
responsible preservation occurrence carries continuity. Identity adds no
independent constitutional information.

### Subjects and destinations

Locality grammar also uses `first_subject_identity`,
`second_subject_identity`, and `destination identity`. These appear to carry
opaque addresses for the exact bounded subjects or destination. If no exact
reference is otherwise carried, the address may be mechanically required.

An opaque destination address does not establish a universal Identity relation,
that two localities are one, or that two addresses are constitutionally
different subjects. The exact locality relation still requires its own
occurrence, Evidence, limits, and participants.

### Disposition

**Reducible where paired with an exact reference; irreducible as opaque machine
address where it is the only retrieval coordinate; constitutional meaning
Unknown.**

## 8. Position-coordinate references

### Location and current claim

`01.Source.D` and `01.Source.D.2` say position-coordinate references identify
one exact byte occurrence. The shared-position road requires the second
coordinate reference of one Assertion and first coordinate reference of
another to address one exact byte occurrence.

### Actual distinction

Each exact coordinate reference resolves through one intact direct Measurement
result to one exact source-position coordinate and its occurrence. The road
uses those resolved coordinates to establish an ordered path. Scalar byte
material and scalar position establish no occurrence.

### Chronology

Commit `d73c4038` introduced much of this wording while deliberately removing
equality from the position road. Identity therefore served partly as a
replacement vocabulary during an equality cleanup. That chronology does not
independently recover a constitutional Identity relation.

### Elimination

Exact reference resolution expresses the same structural crossing. Replacing
equality with Identity was not necessary to say that both exact references
resolve to the addressed occurrence coordinate.

### Disposition

**Reducible to exact reference resolution.** This establishes neither byte
meaning nor equality.

## 9. Grammar root references

### Location and current claim

Each `grammar.json.root_references` entry now has:

```text
this --identifies--> Witness / Grammar / Book / Seed / ...
```

### Chronology and machine boundary

Before commit `fe6bd773`, each root had only a reference and coordinate. That
commit added the `first_subject`, `relation`, and `second_subject` fields and
updated tests to require them. It amended no active Book clause.

The triples carry no responsible occurrence, Evidence, Authority, Scope, or
Standing. The witness grammar separately records that Grammar identifying Book
is not established, even while the root array uses `identifies` as syntax.

### Elimination

Reference and coordinate were already sufficient to address each root. Removing
the positive-looking relation fields loses no machine root.

### Disposition

**Reducible machine-witness syntax; not established relation Standing.** A
grammar witness cannot establish `identifies` by using it to name itself.

## 10. The explicitly evidenced `identifies` relation

### Location and current claim

`01.Standing.E` says one bounded relation Assertion may assert that `X
identifies or represents Y`. Material may carry that Assertion without
supporting it. A responsible occurrence may establish the exact relation within
Evidence, Authority, Scope, provenance, conflicts, loss, limits, and Unknown.

`01.Source.F` likewise permits supplied material to assert that relation while
denying that labels, reference resolution, shape, or repetition support it.

### Vacancy and elimination

The relation position is not vacant: active material already names the
`relation Assertion` coordinate. `identifies` is possible content of that
coordinate, not a universal coordinate shared by every subject.

Removing it would lose the ability to carry and, under an exact responsible
occurrence, establish that exact asserted relation. Therefore it must not be
silently rewritten as reference resolution or preservation.

Active material does not recover what constitutional content distinguishes
`identifies` from `represents`, what observations would establish it, or whether
it is irreducible. Existence of the relation label is not proof of its meaning.

### Disposition

**Unknown, potentially irreducible relation content.** It is Standing-gated and
cannot be inferred from machine addresses, equal strings, repeated references,
co-presence, or grammar shape.

## 12. Cross-domain stress

### Same material, separate recorded occurrences

Two recorded Ingest occurrences may carry the same exact bytes. The bytes
establish neither occurrence and no relation between them. Each occurrence must
be independently present and addressable. This needs occurrence records and
references, not universal Identity.

### One reference repeated

Repeating one exact event reference retrieves the same stored record and does
not append or establish a second occurrence. This is reference behavior and an
explicit non-creation boundary.

### Preservation across Locality

A responsible movement occurrence may carry an exact Assertion reference and
its established coordinates into another Locality. The preservation relation,
not address equality, establishes that carriage.

### Grammar root

`this_Book` is an address in the witness grammar. Its presence cannot establish
that the witness Grammar constitutionally identifies the Book; the witness
itself records that relation as not established.

### Mathematical material

The byte representing `=` can be addressed by occurrence and coordinate
references without establishing equality or Identity. Two references resolving
through exact direct results to the addressed position support the bounded
position road only. Meaning remains Unknown.

### Explicit relation assertion

Material may carry `X identifies Y`. Reference adjacency, repeated labels, or
co-presence supplies no support. Only an exact responsible occurrence may
establish that relation, and its meaning remains bounded by the relation
Assertion's unrecovered content.

## 14. Vacancy result

No vacancy requires universal Identity:

- record lookup is occupied by opaque machine addresses;
- occurrence continuity is occupied by exact occurrence references;
- Assertion continuity is occupied by exact Assertion references and
  preservation;
- subject continuity requires an exact subject coordinate or reference;
- Yield endpoints are occupied by exact Act-occurrence and result references;
- relation content already has the `relation Assertion` coordinate.

The remaining unrecovered distinction is narrower:

> What exact content does the evidenced relation `X identifies Y` carry that is
> not already an opaque address, exact reference, preservation relation, or
> represented relation?

Current active material does not answer that question.

## 15. What this report does not establish

This report establishes no amendment, admission change, rename, migration, or
runtime requirement. It does not establish that all Identity wording is wrong,
that two references establish non-identity, that machine identifiers should be
removed, or that `identifies` and `represents` are one relation. It does not
establish equality, sameness, membership, classification, predication, or
equivalence.

The bounded result is only:

```text
machine addressability                 real mechanism
exact reference                        real coordinate
preservation                           real relation
recorded occurrence distinctness       recoverable without Identity
generic README Identifies              presentation shorthand
subject / identity family              historical orientation compression
root identifies triples                machine-witness syntax
evidenced X identifies Y               exact relation content: Unknown
universal constitutional Identity      not recovered
```
