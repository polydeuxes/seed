# Placement, Movement, Emission, and Source census 001

## Question

Does ordinary `placement` name a missing Seed coordinate between exact result
content and a later material operation, or does it compress distinctions that
the Book already separates as Movement, Emission, Source, and recorded
occurrences?

This is a read-only census after
`gzip_witness_result_later_act_subject_experiment_001.md`. It changes no
runtime road, Book clause, Witness Grammar, or admission. Placement, command,
path, file, process, and filesystem are ordinary report-local terms.

## Positive Movement control

The gzip path experiment records the exact Witness material result:

```text
R = b"/usr/bin/gzip\n"
```

Existing byte Measurement addresses `R`. Its exact source-material result
position carries `R` by occurrence identity. `03.Movement.A` can then carry a
supported exact result position into a separate Locality.

A live control moved the first pair position derived from `R`:

```text
Witness result R
        ↓
position Measurement result M
        ↓
M result position 0
        ↓
Movement binding, Act, and result in destination Locality
        ↓
later pair Measurement dereferences R through M:0
```

The moved coordinate retained:

```text
M occurrence identity
M result position 0
exact pair b"/u"
exact source positions in R
source and destination Localities
```

The later Measurement produced thirteen exact pair findings without another
`b"/usr/bin/gzip\n"` material occurrence.

Thus Movement is real result-to-later-Act composition across Localities. The
content need not be copied or reauthored for a later Measurement to address
it.

## What Movement does not do

The Movement binding, Act, and result all carry `exact_material = None`.
The destination Locality contains no new exact material source result.

The moved subject remains the exact result-position reference:

```text
(M occurrence, M result position 0)
```

It does not become:

```text
a path material result
a filesystem-object coordinate
an operator command
material accepted by a destination boundary
```

Movement therefore changes where an exact result-position coordinate can
participate. It does not turn the addressed coordinate into a new material
source occurrence.

## Emission is a separate coordinate domain

Active Book law already defines the neighboring material-boundary physiology.

`07.Emission.A` addresses:

```text
exact source material result
exact destination boundary
Locality
exact Emission Act
```

`07.Emission.C` makes the exact material accepted by the boundary and the
boundary-reported count exact result coordinates. `07.Emission.D` separately
addresses material supplied within the destination Locality.

That is not Movement:

```text
Movement
    carries an exact result-position coordinate into a Locality

Emission
    addresses exact source material to an exact destination boundary
    and records what that boundary accepted

Source
    addresses material supplied within the resulting source boundary
```

There is currently no active Emission writer or reader in `seed_runtime`.
Book law preserves the distinction, but no live runtime occurrence supplies a
positive boundary-write specimen.

## Recorded is orthogonal

Source, Measurement, Movement, Act, relation, and result occurrences can be
recorded in the Ledger. Their recorded occurrence does not say that one of the
other Acts occurred.

For the live Movement control:

```text
Movement occurrence recorded       yes
Movement result recorded           yes
new material source result         no
Emission occurrence                no
destination-boundary acceptance    no
```

`Record` is ordinary shorthand here, not a recovered Act. The exact distinction
is that these are recorded occurrences. That distinction does not replace the
coordinate carriage or boundary acceptance addressed by Movement and Emission.

## Existing runtime stops

The active roads have exact admission boundaries:

```text
operator Source
    accepts newly read OperatorBoundaryMaterial

operator destination Locality
    accepts an intact operator material result beginning with b"!"

Witness Source
    accepts newly supplied Witness bytes with command and Locality references

Movement
    accepts supported exact result-position references
```

None accepts a Movement result as a replacement operator command or a new
material source result. The host invocation provider receives only the exact
fresh operator command bytes. It does not read Ledger result positions.

An operator Source Act may occur after a Movement result and name it as the
prior reading boundary. That establishes occurrence order. Its subject remains
the newly read operator boundary, so order does not imply use of moved content.

## Placement decomposition

Ordinary `placement` can describe several different exact states:

```text
coordinate available in another Locality       Movement
material accepted by a destination boundary    Emission
accepted material supplied in that Locality     Source
an occurrence present in the Ledger              recorded
```

Those states vary independently in the controls above. Placement therefore
has no single recovered Book coordinate in this census.

For gzip, the current exact stopping point is:

```text
path-shaped Witness result
→ Measurement
→ optional Movement
→ later Measurement or Compare
```

The road does not yet reach:

```text
exact source material result
+ exact destination boundary
→ Emission
→ boundary-accepted material
→ supplied destination material
```

## Next falsifier

The next pressure belongs on the destination boundary, not on a new Act word.

Find an existing live boundary that can independently distinguish:

```text
exact source material addressed to it
exact material it accepted
its reported accepted count
material subsequently supplied in its Locality
```

The operator input stream is currently supplied from outside Seed. The host
provider's process input is private mechanics and is presently `DEVNULL`.
Neither can be promoted to an exact Emission destination merely because a test
can write bytes there.

If no existing boundary supplies those coordinates, the exact result is a
runtime vacancy under already-admitted Emission law. Placement, Use, Request,
Search, or another Source family adds no missing distinction.

## Disposition

Movement survives as exact coordinate carriage. Emission survives as exact
material-boundary writing. Source survives as exact supplied-material
physiology. Recorded occurrence remains a separate exact distinction; no
`Record` or `Recording` Act is recovered here.

Placement remains ordinary compression across those coordinate domains. The
next experiment should census concrete destination boundaries before any
runtime implementation.
