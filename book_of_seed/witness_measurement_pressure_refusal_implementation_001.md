# Witness Measurement pressure refusal implementation 001

## Question

What must stop after one exact material result from this Witness is available
but lacks the exact Locality occurrence and Evidence required by active
`01.Source.D`?

This implementation does not recover the Witness material-acquisition
Responsibility assignment, material Locality physiology, positive assignment
Standing, another scheduler, or any presentation road.

## Recovered boundary

One bounded Locality reconstruction can contain an exact acquisition result
without carrying positive Standing for that result:

```text
one exact Witness material-acquisition result supplied within O2
available through B
!= exact material --Locality--> this Seed
!= Locality occurrence
!= Locality Evidence
!= Measurement assignment warrant
```

The active operator-material road supplies an existing positive discriminator.
Its O1 result carries three independently readable requirements:

```text
exact material --Locality--> this Seed
Locality relation occurrence
intact Locality Evidence
```

The implementation uses that positive operator-acquisition surface only as a
refusal boundary:

```text
one required coordinate absent
→ no declared Measurement pressure

all three coordinates present
→ this prerequisite is present
!= positive Measurement-assignment Standing
```

## Complete active cut

The position-coordinate Measurement source read now excludes an acquisition
result unless the exact operator-acquisition Locality requirements are intact.
Its independent assignment and carried-read checks apply the same refusal.

The exact-byte Measurement road had a separate bypass: it scanned acquisition
results in each declared source Locality directly. That scan now excludes every
result lacking the same required Locality occurrence and Evidence. The declared
Measurement traversal therefore cannot rediscover a raw Witness result supplied
within O2 through a second source surface.

The recurrent-pair-position Measurement assignment and assignment reader now
revalidate the exact source result's Locality prerequisite. A recorded pair or
acquisition identity alone is not enough.

The lower recorded-pair Compare road no longer interprets provenance supplied
by this Witness as a comparison input relation:

```text
exact Witness provenance
!= Applicability
!= Participation
!= Compare input relation
```

The operator console no longer constructs a pair premise from available
acquisition results. It can reuse only an already-carried pair Measurement
whose exact assignment source coordinates resolve to operator-acquisition
results carrying the required Locality occurrence and Evidence.

For each Witness material-acquisition result supplied within O2, the console
still advances the bounded Locality reconstruction and runs the existing
declared-Measurement traversal. The traversal returns no result for that raw
Witness acquisition. An explicit runtime refusal prevents that absence from
silently regressing.

## O ruler

O1, O2, and O3 are external names for actions in one interaction. They are not
Seed occurrence numbers and do not impose adjacency or cardinality inside the
runtime.

Therefore:

```text
O2 crosses from this Witness
↓
zero, one, or thousands of internal occurrences may later occur
↓
our next external action is named O3
```

This cut establishes only that availability of raw Witness results within O2
cannot use the removed shortcut. It does not establish that O3 follows
immediately, that Seed records only one occurrence per bounded surface, or that
one Representation or emission must result.

## Remaining coordinates

`Gate A` and `Gate B` are Rosetta labels for sets of absent coordinates. They
do not name Seed kinds, Acts, or one occurrence that a developer must choose.

```text
GATE A — Rosetta absence set
exact Witness boundary condition
↓

↓

↓

GATE B — Rosetta absence set

↓

+ exact relation occurrence
+ exact Locality Evidence
↓

↓

↓

```

The second set may eventually arise from one, many, or no applicable
Responsibilities as Seed exhausts an exact boundary. This implementation does
not select an occurrence to produce it and does not impose an internal
occurrence count.

Neither absence set is fabricated here. In particular, callback provenance,
`locality_identity`, `scope_locality`, acquisition presence, and
`source_role = "this Witness"` establish neither gate.
