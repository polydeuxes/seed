## Performance findings

The first implementation scanned the complete Python byte population once for
every enumerated aperture and loaded/split an entire 29 MB dictionary to obtain
one 300-line window. Five natural windows consumed about 23 seconds and the run
did not reach the remaining sources inside the execution yield.

Two behavior-preserving corrections were made in the observer:

- bounded `bytes.find` replaces Python iteration over every byte for every
  aperture;
- source files stream only through the exact requested 300-line window.

The nine-source byte run then completed in 19.4–22.9 seconds. The seventeen-
source byte run completed in 45.05 seconds; the scalar control completed in
42.03 seconds. No individual aperture exceeded 1.7 seconds.

The bottleneck exposed a broader compression too: materializing all relations
for every possible aperture is not the same as preserving the smaller set of
source-addressed recurrence results. This observer retains aggregate counts for
the larger population and exact coordinates for the recurrent population.
