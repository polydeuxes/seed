# Repeated-material recurrent-pair position activation investigation 001

## Question

Why does the repeated sixteen-book road stop after pair count and recurrence
Assertions instead of continuing through the existing recurrent-byte-pair
occurrence-position Measurement?

This investigation changes no Book, grammar, runtime, test, acquisition,
Measurement, Candidate, or Compare behavior.

```text

```

`measurement_of_recurrent_byte_pair_occurrence_position.py` explicitly names


Witness source boundaries inside the same invocation Locality.

The first acquisition followed the existing live road:

```text
b"tatatata"
→ exact-byte Measurement

→ recurrence Assertion for b"ta"
→ recurrence Assertion for b"at"
```

The second acquisition retained a distinct acquisition occurrence but repeated
no base position, exact-byte, pair-count, or recurrence work. Its exact bytes
therefore exercised the pointer correction without erasing the later
occurrence.

Those exact carried coordinates were then supplied to the existing recurrent
position functions without changing repository files:

| coordinate | result |
|---|---:|
| recurrence subjects | 2 |

This proves the existing Measurement accepts the exact live-produced subject

It does not prove automatic console continuation. The test probe called the
existing Measurement functions after the console returned.

## Ordinary repeated invocations cross Localities

The repeated sixteen-book experiment uses two ordinary `!cat` invocations.
Each invocation lawfully receives a distinct invocation Locality:

```text
first pair Measurement Locality
operator_invocation_locality_000002

second exact acquisition Locality
operator_invocation_locality_000003
```

Supplying the earlier recurrence Assertions and the second acquisition to the
existing bulk Measurement produces:

```text
ValueError:
pair subject and measured source have distinct Localities
```

This is not an incidental console mismatch. The module contract says the later
material result is in the same Locality, and
`test_distinct_locality_and_pre_source_boundary_are_refused` explicitly proves
that a source in another Locality cannot enter the Measurement.

Both material results carry their exact material-to-this-Seed Locality
relations. That does not erase their distinct invocation Locality coordinates,
and this investigation does not treat the common second subject `this Seed` as
permission to collapse those coordinates.

## The occurrence limit has no live owner

Every Measurement entry point requires a positive exact `occurrence_limit`.
That limit belongs to the result Scope and is preserved with exact known loss:

```text
available occurrence count
carried occurrence population bounded by exact limit
known loss where available count exceeds carried population
```

The tests supply the limit directly. Their common fixture uses `16`, while the
known-loss witness deliberately uses `2`. The live console carries no input,
Responsibility coordinate, or invocation coordinate that supplies this limit.

The small proof used `16` only because each `tatatata` recurrent pair has
exactly 16 available ordered positions, so the proof carries the complete
population and no known loss. It does not establish `16` as the limit for an
arbitrary live material result.

Defaulting the console to `16`, deriving a limit from byte length, or attempting
the complete Cartesian position population would add policy that the existing
live road does not carry.

## Shared position and ordered path proof

The next existing consumer after recurrent-pair position Measurement is the
shared-position Measurement. It requires two exact addressed pair-position

equals the first position coordinate of the second.

The same in-memory proof continued through that existing road. From the two
recurrent-position results it resolved 32 exact position references, addressed
an overlapping `b"ta"` then `b"at"` pair, and recorded:

```text
shared-position Applicability result = applicable

complete durable event population = 78
```

The exact lifecycle was:

```text

→ Applicability Act occurrence

```

This proves that the existing recurrent-position results already have a lawful
consumer and that the road can reach an ordered relation path. It addresses

make the recurrence Assertions participate again.

The proof remains caller-addressed. No current function derives exact
shared-position subjects from the recurrent results; callers address each pair
before Applicability. The family also does not refuse a repeated result for the
same exact pair before append.

Because the ordinary repeated invocations produce no recurrent-position result,
the live console does not reach shared-position Applicability.

## Exact implementation gaps before decomposition

The recursive experiment stops before the demonstrated road at three current
implementation seams. These are not, merely by existing in a function
signature, three separate constitutional requirements. Their decomposition is
recorded in
`recurrent_pair_position_constraint_decomposition_investigation_001.md`.

First, the live console does not continue the exact result coordinates into
the recurrence population carried by that result:

```text
earlier pair-Measurement result
+ its recurrence Assertion population
+ later same-Locality material acquisition
+ exact completeness boundary
↓
recurrent-position Measurement
```

The existing entry points require the caller to supply every address. The pair
result itself already bounds and carries its recurrence Assertion population;
caller enumeration is not thereby established as required grammar.

Second, ordinary repeated invocations do not carry both subjects under the
same current Locality Standing:

```text
earlier recurrence Assertion Locality I1
+ later material acquisition Locality I2
where I1 != I2
↓
existing recurrent-position Measurement refuses
```

No current Standing Locality continuation or Assertion Locality movement road
carries this exact recurrence subject into the later invocation Locality. The
equality check protects that current boundary in the implementation; equality
of invocation-Locality addresses is not independently established as law.

Third, the current function requires a numeric bound for each result:

```text
recurrent-position Measurement requires exact occurrence limit
+ live console carries no such limit
↓
current entry point cannot be called by the live console
```

Exact finite material bounds the mathematical population, but the sixteen-book
rule would expose 39,175,638,934 ordered position findings. Bounded partial
Measurement and its exact known loss are real distinctions. Caller provision
of a positive integer is only the current implementation shape.

After recurrent-position results exist, the shared-position family still
requires callers to address the exact ordered position-reference subjects.
That later caller-addressing seam is not decomposed by this investigation.

Do not route the corpus through Candidate. Do not delete the Locality equality
check merely to cross the boundary, copy the recurrence Assertion into another
Locality, reuse the test limit, or invent a limit merely to continue the
observation.

The existing road itself is proved through ordered relation path. The live
continuation is not established. The current parameter shapes must not be
mistaken for the distinctions they protect.
