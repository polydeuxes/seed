* **captured transport-boundary bytes** are direct only for `stdin.buffer` or a

* **decoder mechanism testimony** is the stream encoding label or UTF-8 fallback;

## 14. Recovery L — asymmetric counterexamples

### Same bytes, different occurrences

Two ingress runs may record identical direct-boundary bytes and decoded text.
Current topology may say there are two distinct capture, examination, ingress,
span, and projection occurrences/identities whose contents happen to be field-
equal if an external examiner compares them. It currently performs no such
comparison. Recurrence, source sameness, common meaning, importance, and
equivalence remain unestablished.

### Different bytes, same decoded text

Distinct physical histories can produce the same Python string—for example a
text adapter may receive `"é\n"` after an unavailable earlier decoder while a
binary UTF-8 stream supplies `c3 a9 0a`. Current strict decoding under one codec
does not itself demonstrate two different byte sequences mapping to the same
string; many codecs can do so across separate selected mechanisms (for example
UTF-8 bytes and Latin-1 bytes for the same character), but that needs two
evidenced captures and their mechanism testimony. Addressable material retains
only decoded text plus lineage, so the byte distinction is reopenable through
raw capture Events, not intrinsic to `ExactOperatorMaterial`.

### Text-stream adapter

`StringIO("abc\n")` produces re-encoded bytes under stream testimony or UTF-8
fallback. Exactness means exact bytes created by that adapter from the supplied
Python string and exact decoded text at this boundary. It cannot mean exact
physical source or original transport bytes.

A stream may label bytes with an available codec that is not their physical
source encoding. Successful strict invocation proves only those bytes decode
under the selected label. The resulting representation is available; source-
encoding truth, correctness, meaning, and grammar remain Unknown.

### Empty ingress versus EOF

Zero bytes set `eof=True` and cannot enter examination/ingress production. A
delimiter-only line has nonzero bytes, decodes successfully, produces
`ingress_kind="empty"`, retains `"\n"` or `"\r\n"` as exact decoded material,
and has trimmed dimensional content `""`. They are distinct capture and scope
outcomes.

The current span proves one stable address over all decoded characters of one
occurrence. Validation refuses partial, multiple, overlapping, or foreign spans.

candidate-supporting substring.
