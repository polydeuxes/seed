### 3.2 `invoke` and `invocation`

Repository usage gives `invoke` an operational meaning: Seed or a caller calls a
command, tool, operation, source, pipeline, decoder, or other mechanism and thereby
undertakes the authorized operational act. Execution or an external effect—and in
some corridors mutation—may occur, and evidence/results may later be returned or
recorded. The Book and implementation testimony repeatedly distinguish the call
boundary from assertion-bearing branches, execution/effect, and result recording.

The existing grammar preserves, rather than collapses:

```text
selection != authorization
authorization != invocation
invocation != execution
execution != result recording
```

Selection identifies a bounded choice; authorization permits an act; neither
performs the operation. Invocation is associated with command or operation
performance and can enter a corridor with mutation or external operational effect,
though neither effect nor successful execution follows by identity. Presentation
formation, representation emission, applicability determination, and selection are
not invocations. Authorization is not invocation. No exact Book authority assigns
`invocation` a special presentation-forming meaning in this district.

## 5. Four proposed entrances cross-examined without naming R

### 5.1 Failed communicative examination

Proposed shape:

```text
exact communicative examination occurs
-> required grammar relation cannot participate in that act
-> examination produces its bounded result
-> later presentation responsibility may examine that result
```

This is not rejected merely because production lacks an occurrence. It is circular
for the first-contact purpose unless the communicative examination can already
identify its material, participants, act, purpose, and required grammar relation
without consuming the very common-grammar relation the presentation is intended to
help establish. Current Book assignment of a relational examiner does not establish
that non-circular entrance, and it assigns no later consumer of the local result.
Therefore this candidate is **Unknown**, not recovered as non-circular.

### 5.2 Explicit operator request

Arbitrary free-form prose cannot establish a request before its meaning relation is
warranted. An already shared bounded token could work only if a prior binding gives
the token exact meaning; the presently described choice token depends on the very
presentation in question and is circular as an initial entrance. No current explicit
CLI mode, exact closed-choice relation, or other warranted entry surface was found
that means “form and emit this bounded presentation.” Thus an explicit request is
possible in design but no current bounded relation establishes it.

### 5.3 Constitutive operator-ingress rule

The active Book describes a conditional/ordinary possible use when bounded first-
contact presentation is used and denies a compulsory universal first enum. It does
not establish that a bounded presentation must precede any defined class of
operator-origin communicative acts. No operator purpose is inferred before common
grammar exists. A constitutive entrance is therefore absent, not negatively
prohibited.

### 5.4 Explicit implementation mode

Implementation could expose a dedicated CLI/application mode; an operator could
select it; exact syntax could supply a shared mechanical meaning. Those three
possibilities remain distinct from Book assignment of constitutional responsibility
and from present production demand. No such current mode or assignment exists.
Accordingly a future mode could provide a non-semantic mechanical entrance, but it
would be lawful for this constitutional purpose only after authority, result,
consumer, scope, negative authority, occurrence locality, and recurrence are
assigned. Code possibility is not recovered law.
