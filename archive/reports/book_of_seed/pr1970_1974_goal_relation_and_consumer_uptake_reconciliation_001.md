## 12. Evidence Graph representation standing

The graph deterministically reads projected State. For each Fact it resolves
`evidence_ids` and support-linked supporting Facts to Evidence records; creates
nodes, `supports` links, per-Fact views and supporting ids; and separately
preserves unresolved/derivation references. It establishes that **under this
projection method these State references resolved (or did not) and were
represented as graph support material**. It does not examine Evidence assertion
semantics, source competency, authority, applicability, expiry/currentness, or
whether the Evidence proposition actually supports the Fact proposition.

Consequently node existence is not assertion consumption; a `supports` edge is a
projection relationship label, not proven semantic support; and resolved
membership is not admission. The graph node does preserve summary, type,
source-event/run ids, confidence and observed time, but graph construction does
not turn those dimensions into current support standing.

## 13. Fact-confidence consumer Uptake

That invocation is the first exact consumer-local Uptake on this road.

| Material available upstream | Actually consumed for confidence standing |
|---|---|
| Evidence assertion content / payload summary | no |
| Evidence source/type/authority | no |
| Evidence provenance / source run | no, except projected supporting ids are emitted for explanation/navigation |
| Evidence observed time/currentness/expiry | no |
| Evidence confidence and link strength | no |
| resolved membership | **yes, only as `len(evidence_view.evidence)`** |
| supporting ids | yes, copied to result; not used in numeric score |
| contradictions | yes, only count plus reason text; any nonzero count applies a fixed penalty |
| Fact explicit confidence | yes, when distinguishable from source-type default; `max` with count-derived value |

The resulting confidence is 0, 0.50, or 0.75 from support count (then max with
explicit Fact confidence and penalized for contradictions). This is **partial,
lossy, count-level Uptake of the graph's resolved-membership assertion**, plus
Fact explicit-confidence and contradiction-summary Uptake. It is not full
Evidence Uptake and does not establish truth, verification, current Fact standing,
or semantic support. `_fact_confidence` consumes a view produced now; it does not
prove any earlier invocation.

Availability, applicability, admission, consumption, Uptake, reliance and
standing change remain distinct. This consumer makes an implicit local admission
of the count-bearing view supplied under its function contract; its numeric and
explanatory `FactConfidence` is a new consumer assertion. The implementation does
not preserve a separate applicability/admission artifact or durable Uptake event,
so those crossings remain compressed/reconstructible for the present invocation.

## 14. Newly available evidence responsibility

Constitutionally, the lawful topology is:

```text
new attributed evidence becomes available
-> a relevant consumer has a warranted discovery path
-> that consumer (or its expressly responsible boundary) examines local applicability
-> admits or refuses
-> actual consumer-local Uptake
-> possibly revises that consumer's assertion/standing, preserving limits/history
```

The consumer-side responsibility owns relevance/applicability, admission/refusal,
actual Uptake, and its revised assertion. An upstream evidence producer owns
production and attributed availability, not universal delivery or adoption. A
separate routing/discovery responsibility could be warranted, but no universal
push, poll, subscription, or router follows from Uptake grammar.

Current confidence callers discover new evidence only if they invoke the builder
with a State/graph that contains it (or allow the builder to rebuild a graph).
The builder then owns this invocation's count-level consumption and revised
`FactConfidence`. No implementation witness shows notification, subscription,
polling, routing, automatic revision, consumer registry, durable prior result, or
Uptake occurrence record. Therefore evidence recorded is not every consumer
updated; graph/projection rebuilt is not confidence invocation; new support is
not confidence revised. Absence of routing is not automatically a Gap.

**Uptake is the correct canonical family**, because active Book clauses define it
as consumer-side, purpose-local responsible use that may warrant a local assertion.
It is plural across consumers and occurrences, not one global stage or act.
